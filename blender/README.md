# Office World Model — Blender scene

Scene authoring for the [go2_nav](../README.md) project: a procedurally generated
open-plan office for **semantic robot navigation** research, built in Blender and exported
to Gazebo Harmonic as SDF, with a machine-readable semantic map so a planner can resolve
queries like *"go to the rubber duck."*

The whole scene is generated by a script, so it is reproducible and parametric: change a
constant, rebuild, and every desk, wall and light updates.

This document covers the Blender side only — editing and re-exporting the scene. For
running the office in Gazebo with the Go2 robot, sensors, teleop and RViz, see the
[top-level README](../README.md).

---

## Quick start

**Look at the scene in Blender**

```bash
blender ~/go2_nav/blender/office.blend
```

It opens in Solid shading (flat grey). Hover the 3D viewport and press **`Z` → Material
Preview** to see colours and textures, or **`Z` → Rendered** for the full EEVEE lighting.
Press **numpad `0`** to look through the active camera.

**Run the full simulation** (robot, sensors, teleop, RViz) — see the
[top-level README](../README.md#quick-start) instead; this scene is consumed by
`src/go2_nav_bringup`, not run standalone from here.

## Layout

```
blender/
├── build_office.py          generates office.blend + scene_objects.json from scratch
├── export_sdf.py            exports office.blend -> ../src/go2_nav_bringup/{models,worlds}
├── office.blend             the scene (edit here, or regenerate with build_office.py)
├── office.blend1            Blender's automatic previous-save backup
├── office_original_backup.blend   the original empty room, before anything was built
├── scene_objects.json       semantic map: rooms, landmarks, labels, poses
└── assets/                  Poly Haven source models + 4K textures (CC0) -- NOT in git,
                             see "Rebuilding the scene" below to re-obtain
```

Textures are **linked relatively** into `assets/`, not packed — which is why the .blend is
only ~2 MB. Keep `office.blend` next to `assets/` or the links break. For a single portable
file, use *File ▸ External Data ▸ Pack Resources* (inflates it to roughly 500 MB because of
the 4K chess-set maps).

## The scene

A 20 × 20 m floor plate, 3.2 m ceiling, interior spanning `x, y ∈ [-10, 10]` with the floor
at `z = 0`. Metric units throughout, Z-up — matching Gazebo directly, no axis conversion.

Full-height partitions with real doorways divide it into six zones, so navigation requires
actual exploration rather than a straight line across an open box:

| Zone | Bounds (x0,y0 → x1,y1) | Contents |
|---|---|---|
| `open_plan` | -10,-10 → 10,4.6 | 12 workstations in 3 pods, collab table, printer, filing cabinets |
| `conference_room` | 3,3 → 10,10 | Conference table, 8 chairs, whiteboard, wall display, credenza |
| `private_office` | -10,4.6 → -4.4,10 | Manager's desk, guest chairs, display shelf, plant |
| `break_area` | -4.3,4.7 → 2.9,10 | Kitchenette, water cooler, coffee machine, round table, lockers |
| `lounge` | 4.6,-4.2 → 9.8,0.9 | Sofa, two accent armchairs, coffee table, floor lamp, rug |
| `reception` | -4.2,-10 → 3.4,-6.4 | Reception counter, accent backdrop, waiting chairs, plant |

The conference room and private office have doors at `(3.7, 3.0)` and `(-5.4, 4.6)`.
Nine glazed windows (sill 0.9 m, head 2.4 m) light the space, with exterior ground and
buildings visible through them.

**Materials** are entirely procedural: carpet tiles with fibre bump, ceiling tile grid,
painted walls, laminate and wood veneer, brushed metal, fabric, glass. Colour comes from an
acoustic felt panel grid, teal desk dividers, and mustard/rust accent seating.

**Lighting** is 20 recessed ceiling panels (area lights) plus a sun and sky, with a warm
floor lamp in the lounge.

### Navigation landmarks

Alongside the furniture, deliberate markers are scattered on the floor as navigation
targets and distractors: six coloured/textured cubes (red, green checker, glossy blue,
wooden, orange marble, purple stripe) and four traffic cones (orange, red, yellow, white).

The five Poly Haven models are placed in context rather than floating:

| Model | Where |
|---|---|
| **Rubber duck** — *the primary target* | On a desk in pod A, `(-7.87, 1.67, 0.74)` |
| Baseball | On the display shelf in the private office |
| School chairs | Around the break-room table (4 copies) |
| Wooden display shelves | Private office, and against the south wall |
| Chess set | *Removed from the current scene — see Known issues* |

### Cameras

| Camera | Purpose |
|---|---|
| `Cam_Overview` | Wide interior overview from the south-east corner |
| `Cam_OpenPlan`, `Cam_Conference`, `Cam_Break`, `Cam_Lounge`, `Cam_Reception` | Eye-level views per zone |
| `Cam_Duck` | Close-up on the navigation target |
| `Cam_TopDown` | Orthographic floor plan (hide the `ceiling` object first) |
| `RobotCam` | **0.55 m sensor height** — what a mobile robot actually sees |

## Semantic map (`scene_objects.json`)

The ground truth a planner reads. 51 landmarks, each with a human-readable label, a
category, the zone it sits in, and its world pose:

```json
{
  "name": "rubber_duck_toy",
  "semantic_label": "rubber duck",
  "category": "toy",
  "zone": "open_plan",
  "location": [-7.87, 1.67, 0.74],
  "size": [0.21, 0.3, 0.29],
  "is_target": true
}
```

Categories: `workstation` (13), `furniture` (15), `cube` (6), `appliance` (5), `cone` (4),
`decor` (3), `plant` (2), `toy` (2), `game` (1).

The file also carries the `rooms` array — each zone's rectangle, centre, and door position —
for room-level planning.

> `name` is unique; `semantic_label` is **not**. All three desk pods emit
> `"desk / workstation 1".."4"`, so twelve desks share four label strings. Key on `name`.

## Rebuilding the scene

**`assets/` is not in this repository** (514 MB of Poly Haven source textures has no place
in git history — see the top-level `.gitignore`). `office.blend` and the exported
`../src/go2_nav_bringup/models/office_scene/` **are** committed normally and work fine
without `assets/` at all — you only need this section if you want to regenerate the scene
from scratch or re-run `build_office.py`.

To get `assets/` back, download these 5 [Poly Haven](https://polyhaven.com) assets — CC0,
no account needed — as their **4K `.blend` package** (each download unpacks to a
`<name>_4k.blend/` folder with a `textures/` subfolder; place folders directly under
`blender/assets/`):

| Poly Haven asset | Folder this project expects |
|---|---|
| [Rubber Duck Toy](https://polyhaven.com/a/rubber_duck_toy) | `assets/rubber_duck_toy_4k.blend/` |
| [Chess Set](https://polyhaven.com/a/chess_set) | `assets/chess_set_4k.blend/` |
| [Baseball 01](https://polyhaven.com/a/baseball_01) | `assets/baseball_01_4k.blend/` |
| [School Chair 01](https://polyhaven.com/a/SchoolChair_01) | `assets/SchoolChair_01_4k.blend/` |
| [Wooden Display Shelves 01](https://polyhaven.com/a/wooden_display_shelves_01) | `assets/wooden_display_shelves_01_4k.blend/` |

Then:

```bash
cd ~/go2_nav/blender
blender -b --python build_office.py
```

Regenerates `office.blend` **and** `scene_objects.json` from nothing — room shell, furniture,
materials, lighting, cameras, and the semantic manifest. Takes about a minute.

> **This overwrites `office.blend` completely.** Any edits made by hand in the Blender GUI
> are lost. If you have hand-edits you care about, save a copy first — or make the change
> in `build_office.py` instead so it survives future rebuilds.

Useful constants at the top of the script: `R` (room half-size), `CEIL_H`, `WALL_T`,
`SILL`/`HEAD` (window heights). Zone layout lives under *Zone layout*; materials under
*Materials*.

## Gazebo export

```bash
cd ~/go2_nav/blender
blender -b office.blend --python export_sdf.py
```

Re-run this after **any** change to the .blend — save in Blender first. It writes straight
into `../src/go2_nav_bringup/{models,worlds}` — the ROS package that actually gets launched —
so there's no separate copy step to remember. Nothing needs cleaning up in between; it
overwrites what's there.

**What it produces:** one static model (`office_scene`) with **one link per semantic
landmark**, named to match `scene_objects.json`, each carrying its label as an XML comment:

```xml
<link name="rubber_duck_toy">
  <pose>-7.87 1.67 0.74 0 0 0</pose>
  <!-- rubber duck | toy | zone: open_plan | TARGET -->
  <visual name="rubber_duck_toy_visual">
    <geometry><mesh><uri>model://office_scene/meshes/rubber_duck_toy.glb</uri></mesh></geometry>
  </visual>
  ...
```

Design decisions worth knowing:

- **Collisions are primitive `<box>` elements, not trimesh.** Because the scene is generated
  from boxes and cylinders, the exporter emits each object's oriented bounding box directly
  — ~944 of them. Far cheaper and more stable in DART than mesh collision, and it is
  information you cannot recover from an exported mesh.
- **Meshes are glTF binary (`.glb`), Z-up**, modifiers applied. glTF defaults to Y-up, which
  would land the whole office on its side in Gazebo; the exporter forces Z-up.
- **Procedural materials are flattened to representative colours.** The glTF exporter
  *discards* a node-driven Base Color and writes white, so carpet, ceiling, desks and the
  patterned cubes would otherwise all be pure white. Each procedural chain is resolved to an
  average colour first. Image-textured materials (the Poly Haven props) pass through intact.
- **Textures are downscaled to 1K** on export — 44 MB → 8.4 MB.
- **Area lights become point lights.** SDF has no area light type, so the 20 ceiling panels
  export as point lights with shadows off, plus a directional sun.
- Unlabelled parts (chairs, stools, loose props) are collected into a single
  `furniture_misc` link — visible and collidable, but not individually addressable.

**Verified:** `gz sdf -k model.sdf` reports *Valid*; `gz sim -s -r --iterations 200` loads and
steps with zero errors, resolving the `model://` URI and building all collisions in physics.

## Known issues

- **`scene_objects.json` is stale with respect to hand-edits.** It is written by
  `build_office.py`, not by `export_sdf.py`. The chess set was deleted from `office.blend` in
  the GUI, but `chess_set` is still listed as a landmark at `(6.0, -1.6, 0.42)` — a planner
  would try to navigate to an object that no longer exists. Either remove that entry or
  delete the chess set in `build_office.py` and rebuild.
- **Roughly half the meshes have no semantic identity.** 1199 meshes map to only 51
  landmarks. The largest gap is **office chairs**: `make_office_chair()` returns its parts but
  most call sites never group them, so ~40 chairs exist only as loose pieces. Eleven further
  items were built with group empties but never given a `landmark()` call (`stool_0..2`,
  `conference_plant`, `private_office_plant`, `filing_cabinet_0`/`_2`, `bin_open_plan`,
  `private_office_bin`, `art_south`, `art_west`).
- **Gazebo surfaces are flat-coloured.** The carpet grain, checker and stripe patterns do not
  survive export. Fine for lidar or pose-driven navigation; a problem if a policy reads RGB
  and needs the patterned cubes to stay visually distinct. Fixing this means baking the
  procedural materials to image textures.

Rendering itself is no longer a concern: the Go2's onboard RGBD camera has been driven
through this exact scene extensively (see the [top-level README](../README.md)), confirming
real, correct rendering of the exported meshes, materials, and lighting in Gazebo — not just
SDF validity.
